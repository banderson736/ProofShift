# ADR-0019: Target Observation And Connector Capabilities

- Status: Accepted for explicitly assigned PS-0.10C implementation; milestone remains In Progress
- Date: 2026-10-05

## Context And Alternatives

External Verification used IShadowTargetConnector and ShadowTargetContext and rejected ordinary Target systems. This made an independent read-only assurance workflow depend on write authority. Adding Oracle/Db2 to that interface would advertise writes that are neither required nor authorized. Broadening shadow contexts to production targets was rejected because it weakens write-role enforcement.

## Decision

ITargetObserver and TargetObservationContext expose only observation for Target or ShadowTarget roles. Verification consumes that contract. ReaderTargetObserver reuses existing artifact readers and the established target identity canonicalization. ShadowReadObserverAdapter is a compatibility path for isolated projected output, not permission to observe arbitrary systems through a writer. Shadow writers retain their separate prepare/write/complete and isolated role contracts. Recovery mutation/checkpoint capability is explicit and absent from reader-only runtimes; observation cannot implicitly authorize rehearsal or rollback.

Connector capability descriptors and a registry-backed catalog report installed read/discovery/checkpoint/observe/write/binary/inspection/consistency/partition support. Concrete providers remain at composition boundaries; core has no concrete connector/pack dependency. Runtime endpoint/selector/version bindings and graph-derived versus observed-execution lineage remain unchanged.

## Evidence And Scope

A real SQL Server-to-PostgreSQL external Verification regression passed with an ordinary Target role, no shadow writer and SELECT-only target credentials lacking DML privileges. Existing projected Recovery adapters remain isolated. New enterprise readers still require real provider/type/checkpoint integration gates before PS-0.10C acceptance.

## Licensing Boundary

Vendor software is used only for synthetic development, automated tests and integration tests. Oracle is built locally/at CI using Oracle's official source repository and official Free download; Db2 is pulled at test runtime. Server images are not bundled, published, uploaded or redistributed. Commercial provider redistribution is deferred. Oracle.ManagedDataAccess.Core 23.26.301 and IBM's platform-specific Db2 .NET provider 10.0.0.300 are referenced. Both real Oracle Free 26ai 23.26.0 and Db2 Community 11.5.9.0 integrations pass locally. No broader legal conclusions are made.

Sources inspected for this boundary:

- [Oracle Database Free FAQ](https://www.oracle.com/database/free/faq/) and [Oracle Free Use Terms](https://www.oracle.com/downloads/licenses/oracle-free-license.html): test image `oracle/database:23.26.0-free` is generated by the official Oracle build script at pinned source revision `f376ce7eb011e6adaacfa325f4e2aee99e9a0830`; the script downloads Free 26ai media from Oracle's official download endpoint. CI does not require OCR credentials.
- [Oracle managed .NET provider license](https://www.nuget.org/packages/Oracle.ManagedDataAccess.Core/23.26.301/License): separate driver terms, not a server entitlement or a blanket commercial suitability guarantee.
- [IBM Db2 Community Docker documentation](https://www.ibm.com/docs/en/db2/11.5.x?topic=deployments-db2-community-edition-docker): test image is `icr.io/db2_community/db2:11.5.9.0`, with explicit `LICENSE=accept`. IBM describes the image as unsupported and non-production, with published 4-core/16-GB limits.
- [IBM .NET 10 provider license](https://www.nuget.org/packages/Net.IBM.Data.Db2/10.0.0.300/License): identifies L-CVPF-JN2TFC and IPLA i125-3301-15, with authorized-use and transfer restrictions. Public NuGet availability does not establish the required entitlement, Db2 Connect rights, or redistribution permission.

## Local Validation And Remaining Gates

Structured-file tests pass 13/13, including duplicate property rejection and iterator-only smoke fixtures of 20,000 NDJSON and 5,000 XML records; connector scaffold tests pass 6/6. Db2 real integration passed 1/1, including discovery of table/view/types/nullability/primary and unique keys/FK, added-column drift detection, streamed typed reads, `DATE`/`TIME`/local `TIMESTAMP`, exact decimals, CLOB/BLOB/VARBINARY reopen after target identity canonicalization, and ordinary Target observation using a SELECT-only account whose DML attempt is denied. The same test captures one Db2 row, one fixed-width record, one NDJSON record and one binary document; it reports `CrossSystemAtomic=false`, stops Db2, deletes all input files and successfully replays all four sources and the binary blob from the checkpoint. The non-vendor core suite passed 161 tests, 0 failed, 2 Windows symlink-capability skips. Per-provider/file throughput/RSS measurements and remote C acceptance remain open.

Oracle real integration passed locally against the official source-built Free image: scoped discovery, exact NUMBER/temporal values, streamed BLOB/CLOB behavior, read-only target observation with DML denied, source checkpoint capture, Oracle shutdown and checkpoint-only replay passed. Remaining gates are connector configuration schemas/strict unknown-property diagnostics; complete fixed-width/XML discovery and encoding; cancellation/error redaction; cross-provider assurance scenarios; per-provider/file throughput/RSS measurements; and required remote CI. Structured readers stream files but materialize an individual JSON object/XML record subtree; maximum record size is not enforced and gzip is not implemented. Db2 scope is LUW Community only; z/OS, IBM i and Db2 Connect-dependent targets are excluded. PS-0.10C remains In Progress.
