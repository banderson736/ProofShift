# ADR 0023: Sequential Partition-Local Verification Scratch

- Status: Experimental PS-0.10D investigation; sequential local-rule path rejected; bounded scratch-write and authorized workers=8 Medium gates passed; milestone remains In Progress
- Date: 2026-10-07

## Context

Retained cumulative 100k/200k processing is 1,821.961 / 4,078.879 s, with normalized penalties 11.94% processing / 14.69% Verification. Saved query plans are stable and operations/rows approximately linear, while per-operation cost rises. The assigned experiment tests smaller actual/journal SQLite hot sets without concurrency. Retain ADR-0021 durable publication and ADR-0022 immutable expected worksets.

## Decision Under Test

Add operational partitionCount 1/4/8 to VerificationService and the physical benchmark harness. Count 1 is the reference path and skips unnecessary hash work. Count is excluded from configuration, expected-workset requirement identity, rule, Evidence and Recovery semantic fingerprints. No worker pool or partition tasks run concurrently.

The plan owns a generic scratch basis: graph-scoped logical target identity. Version `proofshift-verification-partition-sha256-v2` hashes length-prefixed UTF-8 version, basis, scope and existing typed canonical values; unsigned big-endian SHA-256 prefix modulo count selects the partition. No runtime string hashing. Target duplicates with distinct ArtifactIds therefore colocate. Grouping/timeline/relationship key declarations are represented in descriptors, but unsupported owner-key routing fails closed.

Route each streamed actual target directly to its partition by node-scoped logical identity. Route terminal/pending journal facts by the same target identity when present, otherwise first source node/artifact; retain every multi-source association with the one owning journal entry. Each local database stores actual records, hashes/values/typed keys, journal entries and journal source associations. Do not globally materialize and then repartition. Stable graph-scoped target assignment colocates duplicate logical identities; the adversarial test proves ArtifactId hashing would split one seeded duplicate pair.

Each partition has its own WAL/NORMAL connection and bounded 128-logical-write transaction. Calls are issued sequentially, not parallel. A global-read barrier commits all local writers before querying; deferred parent-only transactions avoid reserving locks on all attached databases. Per-connection scratch synchronization matches the reference profile. Cancellation/failure stops service execution, rolls back unfinished local transactions on disposal and cannot reach global durable completion.

Attach partition databases to a coordinator and expose controlled TEMP UNION ALL read views. Local sequence numbers are mapped to unique operational read sequences (local sequence x 16 + partition ID) across actual values/keys and journal ancestry; these numbers never enter semantic identity. Global queries and ordered streams see all partitions, preserving cross-partition duplicates, relations, groups, timelines and exact decimal aggregates. This design may introduce cross-database query/materialization overhead; measure it rather than assuming smaller files imply faster execution.

The shared expected cache remains one exact-key, checksum-validated, read-only attachment per compatible Verification invocation. Its canonical rows are not copied per partition. Cache schema v2 adds an operational fixed-eight-bucket index over node-scoped logical target identity; a run partition reads the matching bucket set without rebuilding expected semantics. The index is built once at expected publication and its elapsed time/row count are measured. Bucket/hash metadata is excluded from semantic requirement, Evidence and Recovery fingerprints. The single canonical ADR-0021 ledger remains unchanged; staging/finalization is global, with no partition-ledger merge or N receipts.

## Rule Safety and Global Behavior

Descriptors/plan expose exactly `PartitionLocal`, `PartitionPartialWithGlobalMerge` or `Global`, plus a typed partition basis/role/field contract; default is Global. Partial mode is rejected unless the rule provider implements the deterministic merge interface. The current physical router proves only target identity colocation; grouping/timeline/relationship key declarations that require another basis fail closed. Unknown and unproven rules remain Global.

Current non-global generic rules are target presence and attribute comparison (`PartitionPartialWithGlobalMerge`), and unexpected-target plus entity uniqueness (`PartitionLocal`). Pension member attribute comparison uses the generic attribute implementation and the same declared identity key. Local scans filter actual/journal tables in the selected database and expected rows through the shared cache's stable bucket index. Presence and attribute population summaries merge counts globally into the existing canonical finding; artifact findings merge by stable semantic key, detect conflicts, and sort independently of partition number. Partial finding IDs/codes are never published. Exact duplicate identity tests demonstrate local uniqueness remains safe when artifact IDs differ.

Source disposition, target lineage/accounting, member business-key uniqueness/presence/status, all timeline, relationship, and financial aggregate rules remain Global. Timeline/relationship/aggregate owner fields are not the same as the physical identity partition key, so marking them local would be unsound; no grouping-local partial aggregate has been implemented. Global source-disposition, lineage, and final coverage/ledger checks remain authoritative. The deterministic value-free manifest records hash version, key/mode declarations, per-partition artifact counts and skew; high-water resource telemetry remains separate. This continuation therefore proves only the explicitly listed identity-key local rule slice, not the complete future partition-local evaluator architecture or all global hot-set costs.

## Integrity and Validation

Require deterministic typed assignment across repeated child-process execution, forced cross-partition owner/timeline records, exact decimal sum, global duplicate detection, multi-source journal ancestry, cross-partition membership, cancelled writes and corrupted local database failures. Compare identical small physical input at 1/4/8 for finding JSON, ledger/Evidence fingerprints, Recovery assessment/plan/rehearsal fingerprints, qualification and reasons. Run-specific Recovery provenance remains bound to its own Verification ID as before.

The tests exposed an existing G29 scientific-decimal decoding/collation defect (`1E-10`); allow exponent parsing in exact decimal representation without introducing floating point. A separate-connection visibility defect required a flush barrier before attribute comparisons; no assertion was weakened.

## Measurement and Gates

Record per-partition rows, DB/WAL high-water, index count/largest index bytes where dbstat is available, native DML executions/time, committed transactions/time and index-build phases. Report both largest partition and sum of partitions, coordinator and shared expected DB separately. Global cross-partition read duration remains global because SQLite does not provide a truthful per-database split; OS I/O byte attribution is not invented from file size.

Initial Fast showed a four-partition planner regression from materialized key-union LEFT JOIN scans. Actual/key and journal/source ancestry joins must remain native indexed joins inside each partition before deterministic global union/order; global coverage must still check all partitions. Repairs were regression-tested without dropping ancestry or fingerprint assertions. Global-read overhead remains a measured cost, not evidence that partitioning is automatically efficient.

Start with exact Fast and intermediate diagnostics, then compare 100k count 1/4/8 where practical against retained 1,821.961 s. Run 200k only for a credible non-regressing best candidate and evaluate preferred normalized processing penalty at most 8%, targeting 5%, with Verification materially improved. Smaller files with unchanged cost are not a locality win. Broad parallelism is optional only after sequential benefit is demonstrated. Medium/Large/PS-0.10E remain blocked; no alternative backend is adopted.

## Assigned Rule-Local Continuation

The new explicit PS-0.10D continuation supersedes the preceding sentence's stop for this narrow sequential experiment only. Medium/Large, workers, PS-0.10E and backend replacement remain out of scope. The operational assignment version is now `proofshift-verification-partition-sha256-v2`; it hashes the plan-owned graph-node scope plus canonical logical target identity, not ArtifactId. This is required so exact duplicate identities with distinct ArtifactIds cannot be split by local uniqueness checks.

Every descriptor now carries exactly one mode (`PartitionLocal`, `PartitionPartialWithGlobalMerge`, `Global`) and an optional typed key basis/role/field-option contract. Global is the conservative default. Execution-plan construction rejects partial mode without a rule merger and rejects non-identity local key contracts because current storage routing cannot prove their co-location. All generic and Pension descriptors therefore resolve explicitly through provider metadata, without Pension-name checks in Verification.

The current supported identity-local rules are generic target uniqueness and unexpected-target; generic target presence and attribute comparisons execute per partition and merge canonical population findings globally. Pension member attribute comparison reuses the generic provider rule. Pension member presence, uniqueness and status are also local only when exactly one target node is explicitly scoped and its configured/default business key is proven equal to that node's single-field graph selector identity (the reviewed `member_id` contract); graph mismatches or ambiguous node scope resolve to Global and record a fallback reason. All source-accounting, lineage/coverage, other Pension business rules, timelines, relationships, and financial aggregates remain Global. Distinct artifact identities with a common timeline owner are adversarially verified to occupy different partitions, and the beneficiary relationship descriptor remains Global when related artifacts hash differently. No grouped aggregate partial merge or timeline/relationship owner router is claimed.

The canonical expected workset remains one checkpoint-derived immutable cache. Schema/key format v2 adds a stable operational bucket (8 buckets) over target logical identity; partition p reads buckets p, p+N, etc. One index is measured at build and reused; no N expected builds/copies exist. This metadata is excluded from semantic fingerprints. Actual records continue direct streaming to their identity partition. Rule scans set explicit evaluation partition context; local SQL branches read selected actual/journal stores and indexed expected buckets. Final global accounting/lineage/target checks and canonical ADR-0021 ledger staging/publication remain unchanged.

Partition-local findings carry ordinary rule/version/stable semantic keys. Local findings are globally sorted/deduplicated by those keys; conflicting duplicate keys fail closed. Partial population facts merge to the same pre-existing finding code/key/value, with no partition number entering evidence. A deterministic value-free partition manifest fingerprints hash version, rule modes/key definitions and artifact counts; resource sizes stay in separate measurements. Per-rule/per-partition stages carry wall time/finding counts and correlate to scan/decode/lookup telemetry. Partition skew is reported diagnostically, never used as a correctness failure.

Focused Engine 3/3, Verification 38/38, Evidence 5/5 and Recovery 8/8 gates pass. Fast p8, partition assignment/adversarial workspace tests, and physical 1/4/8 semantic equivalence also pass. The sequential local-rule 100k p8 probe completed in 1,663.892 s processing. The authorized 200k p8 probe passed 2/2 physical tests, preserving exact 149/0 discrepancy semantics, zero unaccounted/unexplained artifacts and corrected QUALIFIED output. It produced 206,696 checkpoint artifacts and 209,128 corrected targets; peak RSS was 642,310,144 B and final ledger size was 6,285,037,568 B.

At 200k, ProofShift processing was 3,864.780 s, 21.97% above the retained 3,168.623 s processing reference, so the required <=5% non-regression gate failed. The 1,726.090 s subtotal is the inclusive sum of exact-name `verification` stages, not the complete Verification category. All `kind=4` exclusive Verification intervals total 3,144.050 s for local-rule mode versus 2,575.491 s retained, a 22.08% increase. Processing grew 2.323x from the earlier standalone local-rule 100k result, a 16.14% normalized penalty. Neither end-to-end processing nor complete Verification improved.

## Explicit Bounded-Concurrency Follow-On
